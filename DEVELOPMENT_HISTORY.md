# Steelworks 0.9.6 — equipment and native behavior integration candidate

Target: Vintage Story 1.22.7, EM2 3.8.3, .NET 10. Extract and run BUILD_WINDOWS.ps1. Uses your locally installed game DLLs; none are distributed. Results ZIP goes to Downloads even if compilation fails. A TEST_MOD ZIP is produced only after core tests and native compilation succeed. Test in a disposable world only; do not install on the production server.

## Native content
Generated patches against the supplied vanilla asset archive; 78 tool/weapon variants, 68 heads, 99 smithing variant extensions, six anvils, new native metal properties and 53 missing texture assets derived from vanilla. Existing nickel and cupronickel production unchanged. Native stainless melting point 1530 C retained. Internal native metal tiers are distinct from mining tiers. Native anvil mold requires 900 units; forged costs follow native recipes. Titanium dioxide + crushed coal is a simplified gameplay conversion. Iron Blend creates cast iron in the crucible or blister steel at 1450 C in the furnace (solid-state gameplay conversion, not actual melting). Heat treatment for specialty steels is a candidate native integration. Handbook has six guide pages and localized item descriptions.

## Furnace
3x3x6 with two steel hatches, three tiered containers, native refractory bricks/gratings and physical coke. Layers bottom to top: foundation, lower coke chamber and refractory intake, upper coke chamber and fuel hatch, grating, alloy container, loading hatch. Hatches and intake can occupy any of the four appropriate side centers. Shift-right-click on the intake to show preview; Shift-Ctrl-right-click to hide. Right-click toggles hatches with held items; specialized interactions take precedence. Load coke through the open fuel hatch and ignite with a firestarter before or after loading blends. Close both hatches to preheat; aim bellows into the intake. Open top hatch and Shift-right-click to load up to 160 blends of one type, in multiples of 20 for processing. Once processing starts, the charge is locked. Finish the batch to stop burning automatically, or Shift-right-click an open fuel hatch with empty hand to stop. One hammer hit releases hardened ingots; tongs are required at 200 C or hotter. Retrieved metal keeps its temperature and may need reheating for smithing. Refractory intake, brick and grating wear uses the existing tier rates; the container never wears. Server settings and fuel rates unchanged. No dedicated TG bellows integration.

## Client renderer
One renderer is attached to each loaded hatch controller and renders the container one block below it. It reads the existing synchronized state, uses the game's standard shader, native incandescence and mesh primitives. Twenty blends fill one cavity continuously. Charged molds show their blend texture, then hot product surfaces during conversion above melting point (except the solid-state blister steel recipe). Output cooling uses vanilla-style liquid/soft/hardened thresholds; hardened contents use a smaller solid mesh and rise slightly on release. Renderer uses a 24-block distance limit, cached texture locations, reusable quad and cube meshes, and disposes GPU meshes on unload/removal. A render exception is logged once and disables that renderer until reload. Legacy 0.9.4 filled-container IDs are retained to allow existing saves to resolve; on server update these are exchanged for the normal empty shell. No new charge or heat block variants are registered. The renderer does not modify inventory or simulate furnace processing.

## Test checklist
1. Check client/server startup logs for JSON patches, duplicate assets, unresolved codes, recipes and class errors. Search handbook/creative for Steelworks and each alloy. Inspect textures, smithing patterns, tool tiers and anvil tiers. Test cast iron and cupronickel casting and forged anvil parts. Verify native steel/nickel recipes unchanged.
2. Construct furnace with each refractory tier; check preview, rotate, damage and repair. Verify coke loading, actual inventory conservation and bellows strokes (manual and mechanical). Verify no airflow when not pumping. Test external modded bellows using native interface or explicit API.
3. Process 20 and 160 blends. Verify temperatures, pauses, fuel depletion, wear, cooling, one hammer hit and retrieval. Restart server mid-batch and after release. Verify no duplicate drops when breaking/replacing components. Verify player permissions and multiplayer synchronization.
4. Check tooltips/handbook entries and recipe navigation; test steel heat treatment and native steel refining.

## Known limitations
0.9.5 compiled and selected gameplay mechanics were user-tested. 0.9.6 is a source-only candidate: the environment does not have the .NET SDK or a running 1.22.7 client, so new native API calls, runtime textures, shader behavior, UV alignment, control hints, tongs handling and gameplay tests are not verified. The dynamic renderer uses vanilla API primitives and shader methods, not the vanilla mold entity directly. Visual melting does not change batch accounting. Hardening follows the vanilla mold 30% melting-point boundary; even with hot tongs retrieval, reheating may be required for smithing. Vanilla public source was used as API reference; exact binary compatibility must be confirmed by compilation. Existing controller sync sends state on the current one-second server tick, unchanged in cadence. No release-ready claim. Back up your world and test in the disposable world first.

Third-party recipe assets: config/steelworks/furnace/*.json in your mod domain, matching the included schema. Use qualified input/output IDs, 5 units per blend, unique code/input, temperature below 1800, positive processingTimeHours. Registry resolves item codes after assets load. Ingot IDs are game:ingot-cupronickel, castiron, nickelsteel, stainlesssteel, chromesteel, titanium. Native game properties and texture paths are available to dependent mods. Depend on steelworks and EM2. No duplicate nickel.
